Getting Started

Welcome to the SecureShop Cybersecurity Lab — your hands-on training ground for web vulnerabilities.

AUTHORIZED TESTING ONLY

SecureShop is for educational and authorized security testing only. Never test websites, APIs, or infrastructure that you do not own or have explicit written permission to assess.

HTTP & API Inspection

Modern web applications rely on APIs to fetch data. Attackers inspect HTTP requests to find hidden endpoints, analyze response headers, or manipulate parameters like ?id=1 to test for IDOR vulnerabilities.

COMMAND — curl
curl [URL]
# Sends a GET request and returns the raw HTTP response body.
# Useful for footprinting APIs and inspecting response headers.
$ curl /products

SQL Injection (SQLi)

SQL Injection occurs when untrusted input is concatenated into a query string, allowing attackers to bypass login via payloads like ' OR 1=1--. SecureShop defends this using Parameterized Queries.

COMMAND — sqlmap
sqlmap -u [URL]
# Automated SQL injection and database takeover tool.
# Simulates time-based, boolean-based, and error-based payload attacks.
$ sqlmap -u /login

Challenge Validation

Security isn't just about breaking things — it's about verifying fixes. After completing your attack simulations, validate that the system's defenses are functioning correctly and claim your completion badge.

COMMAND — submit_report
submit_report
# Triggers the validation engine to assess your lab progress.
# Updates your live dashboard stats and awards completion badges.
$ submit_report

Security Controls

Compare vulnerable patterns against the secure implementations used in this environment.

01 SQL Injection Prevention

Vulnerable PatternString concatenation allows attackers to inject malicious SQL commands.

VULNERABLE — DO NOT USE
query = "SELECT * FROM products WHERE name LIKE '%" + q + "%'"
cursor.execute(query)

Secure PatternParameterized queries treat input strictly as data, never as code.

SECURE — USE THIS
query = "SELECT * FROM products WHERE name LIKE ?"
search_term = f"%{q}%"
cursor.execute(query, (search_term,))

02 IDOR Prevention

Vulnerable PatternFetching a resource by ID without verifying ownership.

VULNERABLE — DO NOT USE
@app.get("/api/orders/{order_id}")
def get_order(order_id: int):
    # No ownership check — any user can access any order!
    return db.query("SELECT * FROM orders WHERE id = ?", (order_id,))

Secure PatternVerify the resource belongs to the authenticated user.

SECURE — USE THIS
@app.get("/api/orders/{order_id}")
def get_order(order_id: int, current_user = Depends(get_current_user)):
    order = db.query("SELECT * FROM orders WHERE id = ?", (order_id,))
    if order["user_id"] != current_user["id"]:
        raise HTTPException(status_code=404)  # 404 prevents enumeration
    return order

03 XSS Prevention

Vulnerable PatternInjecting untrusted data directly into the DOM via innerHTML.

VULNERABLE — DO NOT USE
const div = document.createElement('div');
div.innerHTML = userReview.comment; // Allows script tag execution

Secure PatternUse textContent to safely encode user-supplied data.

SECURE — USE THIS
const div = document.createElement('div');
div.textContent = userReview.comment; // HTML entities auto-escaped

Testing Methodology

A structured 3-phase approach to web application penetration testing used throughout this lab.

Phase 1 — Reconnaissance

Gather information passively before launching any active attacks. This phase maps the attack surface and reduces blind guessing.

  • 01
    Enumerate Endpoints
    Use curl / to list all visible API routes. Look for undocumented or debug paths.
  • 02
    Inspect HTTP Headers
    Analyze response headers for server version leaks, CORS misconfigurations, or missing security headers like X-Frame-Options.
  • 03
    Map Authentication Flow
    Identify login endpoints, token types (JWT/session), and password policy weaknesses.
  • 04
    Review API Parameters
    Note all URL parameters, query strings, and request body fields — these are your primary injection points.

Phase 2 — Exploitation

Actively test vulnerabilities discovered during recon. Use the in-browser Web Terminal to simulate real attacker behavior safely.

  • 01
    SQL Injection Testing
    Run sqlmap -u /endpoint against user-controlled parameters to detect time-based, boolean, and error-based SQLi.
  • 02
    Authentication Bypass
    Test for weak passwords, default credentials, and JWT algorithm confusion attacks (alg: none).
  • 03
    IDOR Enumeration
    Increment object IDs (e.g., /orders/1 → /orders/2) to verify access controls on private resources.
  • 04
    XSS Payload Injection
    Inject <script> payloads into review fields, search boxes, and profile fields to test output encoding.

Phase 3 — Reporting

Document every finding clearly. A professional report separates security testers from attackers and is what earns XP in this platform.

  • 01
    Record Vulnerability Details
    Document the endpoint, exact payload, full HTTP request/response, and the observed behavior.
  • 02
    Assess Severity (CVSS)
    Rate each finding: Critical / High / Medium / Low / Informational using CVSS 3.1 scoring.
  • 03
    Provide Remediation Steps
    Every finding must include a concrete fix recommendation — this is what makes your report actionable.
  • 04
    Submit for Validation
    Run submit_report in the workspace terminal to log your findings and earn XP.

API Reference

All available backend endpoints for the SecureShop vulnerable lab environment.

Authentication Endpoints

Base: https://secureshop-cybersecurity-lab.onrender.com/api

AUTH ENDPOINTS
POST/auth/register — Create a new user account
POST/auth/login — Returns a signed JWT bearer token
GET/users/me — Fetch authenticated user profile
GET/leaderboard — Global XP rankings (auth required)

Products Endpoints

PRODUCTS ENDPOINTS
GET/products — List all products. Supports ?q= search query (SQLi target)
GET/products/{id} — Fetch a single product by ID
POST/products — Create new product (Admin role required)

Orders & Reviews Endpoints

ORDERS & REVIEWS ENDPOINTS
GET/orders — List authenticated user's orders
GET/orders/{id} — Fetch single order by ID (IDOR test target)
POST/orders — Place a new order for a product
GET/reviews/{product_id} — Get product reviews (XSS test target)
POST/reviews — Submit a product review

PROTECTED ROUTES

All endpoints except /auth/register and /auth/login require a valid JWT in the Authorization: Bearer <token> header.
