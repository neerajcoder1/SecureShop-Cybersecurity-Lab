SecureShop Lab

Security Controls Documentation

This lab demonstrates secure coding practices to prevent common web vulnerabilities.

1. SQL Injection Prevention

Vulnerable Pattern (DO NOT USE): String concatenation allows attackers to inject malicious SQL commands.


# INTENTIONALLY VULNERABLE PATTERN
query = "SELECT * FROM products WHERE name LIKE '%" + q + "%'"
cursor.execute(query)

Secure Implementation (Used in this Lab): Parameterized queries ensure input is treated strictly as data, not executable code.


# SECURE PATTERN
query = "SELECT * FROM products WHERE name LIKE ?"
search_term = f"%{q}%"
cursor.execute(query, (search_term,))

2. IDOR (Insecure Direct Object Reference) Prevention

Vulnerable Pattern (DO NOT USE): Fetching a resource by ID without verifying ownership.


# INTENTIONALLY VULNERABLE PATTERN
@app.get("/api/orders/{order_id}")
def get_order(order_id: int):
    # Missing authorization check!
    return db.query("SELECT * FROM orders WHERE id = ?", (order_id,))

Secure Implementation (Used in this Lab): Verifying the requested object belongs to the authenticated user.


# SECURE PATTERN
@app.get("/api/orders/{order_id}")
def get_order(order_id: int, current_user = Depends(get_current_user)):
    order = db.query("SELECT * FROM orders WHERE id = ?", (order_id,))
    if order["user_id"] != current_user["id"]:
        raise HTTPException(status_code=404) # 404 prevents enumeration
    return order

3. XSS (Cross-Site Scripting) Prevention

Vulnerable Pattern (DO NOT USE): Directly injecting untrusted data into the DOM using innerHTML.


// INTENTIONALLY VULNERABLE PATTERN
const reviewDiv = document.createElement('div');
reviewDiv.innerHTML = userReview.comment; // Allows script execution

Secure Implementation (Used in this Lab): Using textContent to ensure data is safely encoded.


// SECURE PATTERN
const reviewDiv = document.createElement('div');
reviewDiv.textContent = userReview.comment; // Safely escapes HTML entities
