Getting Started

Welcome to the SecureShop Cybersecurity Lab — your hands-on training ground for web vulnerabilities.

AUTHORIZED TESTING ONLY

SecureShop is for educational and authorized security testing only. Never test websites, APIs, or infrastructure that you do not own or have explicit written permission to assess.

HTTP & API Inspection

Modern web applications rely on APIs to fetch data. Attackers inspect HTTP requests to find hidden endpoints, analyze response headers, or manipulate parameters like ?id=1 to test for IDOR vulnerabilities.

COMMAND — curl
curl [URL]
# Sends a GET request and returns the raw HTTP response body.
# Useful for footprinting APIs and inspecting response headers.
$ curl /products

SQL Injection (SQLi)

SQL Injection occurs when untrusted input is concatenated into a query string, allowing attackers to bypass login via payloads like ' OR 1=1--. SecureShop defends this using Parameterized Queries.

COMMAND — sqlmap
sqlmap -u [URL]
# Automated SQL injection and database takeover tool.
# Simulates time-based, boolean-based, and error-based payload attacks.
$ sqlmap -u /login

Challenge Validation

Security isn't just about breaking things — it's about verifying fixes. After completing your attack simulations, validate that the system's defenses are functioning correctly and claim your completion badge.

COMMAND — submit_report
submit_report

Security Controls

Compare vulnerable patterns against the secure implementations used in this environment.

01 SQL Injection Prevention

Vulnerable PatternString concatenation allows attackers to inject malicious SQL commands.

VULNERABLE — DO NOT USE
query = "SELECT * FROM products WHERE name LIKE '%" + q + "%'"
cursor.execute(query)

Secure PatternParameterized queries treat input strictly as data, never as code.

SECURE — USE THIS
query = "SELECT * FROM products WHERE name LIKE ?"
search_term = f"%{q}%"
cursor.execute(query, (search_term,))

02 IDOR Prevention

Vulnerable PatternFetching a resource by ID without verifying ownership.

VULNERABLE — DO NOT USE
@app.get("/api/orders/{order_id}")
def get_order(order_id: int):
    # No ownership check — any user can access any order!
    return db.query("SELECT * FROM orders WHERE id = ?", (order_id,))

Secure PatternVerify the resource belongs to the authenticated user.

SECURE — USE THIS
@app.get("/api/orders/{order_id}")
def get_order(order_id: int, current_user = Depends(get_current_user)):
    order = db.query("SELECT * FROM orders WHERE id = ?", (order_id,))
    if order["user_id"] != current_user["id"]:
        raise HTTPException(status_code=404)  # 404 prevents enumeration
    return order

03 XSS Prevention

Vulnerable PatternInjecting untrusted data directly into the DOM via innerHTML.

VULNERABLE — DO NOT USE
const div = document.createElement('div');
div.innerHTML = userReview.comment; // Allows script tag execution

Secure PatternUse textContent to safely encode user-supplied data.

SECURE — USE THIS
const div = document.createElement('div');
div.textContent = userReview.comment; // HTML entities auto-escaped
